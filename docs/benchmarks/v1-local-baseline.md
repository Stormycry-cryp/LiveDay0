# v1 本地参数基准

测试日期：2026-08-07（Asia/Shanghai）。这是本机合成样本的安全起跑基准，不代表生产普遍结论。

## 环境与样本

- macOS 15.6 arm64，Python 3.13.14，PostgreSQL 17.10（Colima）。
- 当前验证镜像没有安装 pgvector，因此本次只测全文、时间、状态和类型化关系候选；pgvector 路径已条件集成，但向量质量和延迟仍未由本次结果证明。
- 1 个租户，160 张规范卡；每组召回 3 次预热、30 次计时；事件有效卡覆盖每组 50 次。
- 命令：`uv run python benchmarks/benchmark_recall.py`。

## 最终采用值

- 单卡 180 tokens、整包 1600 tokens、候选/关系/最终 48/24/12，保留为实现设计初值。
- 每个关系族最多 6 项，作为防高连接节点扇出的确定性硬边界；本样本没有足够关系密度证明应提高。
- 在线记忆超时 800 ms。默认组最大 34.91 ms，在此合成样本上有约 22 倍余量；超时仍按失败降级处理，不能据此承诺生产延迟。
- 事件安静期 60 秒、单事件待合并增量软上限 8 条。8 条覆盖 P95 为 14.07 ms，未显示必须降低；到达软上限会把已合并的唯一任务提前到可执行状态。
- 派生视图 15 分钟陈旧窗口保留为运行目标，不作为正确性豁免；本地 v1 由 `run-jobs` 驱动，没有伪装成已验证的常驻 worker 时延。
- 普通痕迹仍不设固定类别和统一衰减。v1 只保存来源、观察边界和可访问性软信号，本基准不支持推出更细策略。

pgvector 候选、真实生活样本相关率、长期图规模和自动 worker 积压没有在本次环境中得到证据；这些不改变“缺少历史优于错误历史”、完整卡片、租户隔离和硬失效优先等语义边界。
