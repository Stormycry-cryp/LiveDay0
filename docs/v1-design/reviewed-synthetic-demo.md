# 可运行的候选审阅合成闭环

2026-10-11。新命令复用 LocalMemorySession、完整提案、固定差异诊断、terminal_confirmation 和现有 MemoryService。它只演示两句固定爬山合成文字，没有外部模型、密钥或任意生活文字输入。

## 运行

准备项目既有 Python 3.13 依赖和本机 PostgreSQL 17 命令行工具后，在仓库根目录运行：

```sh
uv run liveday0 synthetic-demo --scripted
uv run liveday0 synthetic-demo
```

自动模式用明确标注的合成确认决定，适合复现验收。交互模式需要真人终端：第一次展示候选时输入任意非 SAVE 内容拒绝；第二次输入 SAVE 保存；随后依次用 SAVE 确认更正、卡片删除及两份来源删除。它会展示完整具体范围；不照该演示顺序选择会停止这次演示并保留隔离目录。Ctrl-C 也走停止收尾。合成交互入口不提供通用日记、自动恢复或新增 UI。

默认 PostgreSQL 工具目录是 `/opt/homebrew/opt/postgresql@17/bin`；其他本机安装可显式使用 `--postgres-bin /path/to/postgresql17/bin`。工具缺失则停止，不自动安装或回退到已有数据库。普通项目入口及 `local --demo` 行为保持不变。

## 隔离及保留

每次只在系统 `/tmp` 下创建新的私有 `ld0-synth-*` 目录和唯一标记集群，不接受 PGDATA、数据库 URL 或目标库参数。不继承当前环境的 LIVEDAY0_DATABASE_URL、PG 服务和密码配置；子进程使用固定清洁环境、空密码文件路径，连接自己创建的 Unix socket。没有 TCP listener，socket 和目录权限 0700，host 认证拒绝。

创建者先核实目录、socket、无 TCP、集群标记、数据库注释及零 public tables，再迁移并创建非超管、无 BYPASSRLS/建库/建角色权限的应用登录。记忆操作只用该登录及 liveday0_app。应用进程另外核实实际 socket、数据库注释及自身权限，不授予读取受限配置的角色。实例退出时仅停止本次创建的目录，并核实 PID 不存在；不会停止、清理或删除任何已有库。

结果返回新目录中的 manifest.json、九步回执/检查和确认范围；日志及停止后的合成 PGDATA 保留，不自动删除或重用。若启动/停止失败，检查该新目录的 logs，不拿旧实例续跑。由于都是固定合成材料，报告会保留演示中已删除内容的审阅日志；这不是实际用户删除后的数据保留策略，也不能对真实生活库运行。

## 每一步的验证

| 步骤 | 可验证结果 |
| --- | --- |
| 固定输入→完整候选→拒绝 | 普通候选完整范围先展示；证据、卡片和快照未变化 |
| 同一固定文字→确认 | 普通来源通过 save-candidate 审阅，才保存证据和版本 1 卡片 |
| 检索 | 返回改期及待朋友确认 |
| 明确目标更正 | 按版本 1 更新到版本 2，旧快照失效 |
| 再检索 | 新日期仍在，旧待确认及不确定内容不再作为当前解释 |
| 删除卡片 | 卡片被删除，全部历史卡正文清空，来源解释撤销，旧快照失效 |
| 删除两份来源 | 原文和 locator 都为空，来源 status=deleted |
| 删除后检索 | 原提案正文不再出现 |

更正保留原证据供历史核验，只使旧的当前解释失效；来源擦除是后面的显式删除步骤。不会把两者混成一个操作。

定向测试只运行本批新闭环，不加载 pytest 的建库/清库 fixture：

```sh
uv run python -B tests/test_synthetic_demo.py -v
```

测试通过 public CLI 真正创建、迁移、操作和停止一个新的隔离空库，并故意提供不可用的合成环境数据库地址，证明该地址未被采用。它使用 scripted 确认，不能当作真人终端参与验收。实际真人操作、任意自然语言、真实模型质量、长期关系/生活线索理解及服务器身份仍未验收；本批仅证明固定合成闭环可复现。
